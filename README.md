# H2T-CBD (2026) Documentation

This repository provides the reproducible materials for the paper *Preserving Accuracy and Improving Cross-Prompt Representation Alignment with Selective Anchoring*. It contains all code, environment instructions, paper figures, and NLTK data. Datasets and experiment results are not distributed with the repository; users can reproduce all numbers and figures from scratch by following this document.

## 2. Dataset Sources and URLs

This work uses three public English essay scoring datasets, all from official Kaggle competition pages. The official raw files are not redistributed with this repository; download them from the links below and place them in the specified locations.

The first dataset is ASAP-1, the Hewlett Foundation - Automated Essay Scoring competition, available at https://www.kaggle.com/competitions/asap-aes/data . Download the file `training_set_rel3.tsv` and place it in `data/01_raw_datasets/feat/`. This dataset contains 12,976 essays across 8 prompts. The paper computes 19 linguistic features on it, and it is the core dataset for the cross-prompt analysis.

The second dataset is ASAP-2.0, the Learning Agency Lab - Automated Essay Scoring 2.0 competition, available at https://www.kaggle.com/competitions/learning-agency-lab-automated-essay-scoring-2/data . Download the file `train.csv` and place it in `data/01_raw_datasets/asap2/`. This dataset contains 17,307 essays with scores from 1 to 6; the official file does not include prompt labels.

The third dataset is Feedback Prize - English Language Learning, available at https://www.kaggle.com/competitions/feedback-prize-english-language-learning/data . Download the file `train.csv` and place it in `data/01_raw_datasets/dysf/`. This dataset contains 3,911 essays annotated with six analytic scores: cohesion, syntax, vocabulary, phraseology, grammar, and conventions. In this work, the six scores are averaged and rounded to an integer, producing a single overall writing-proficiency target from 1 to 5.

The ASAP-1 tsv file is decoded as Windows-1252 (cp1252), and the few undefined bytes are replaced; see `code/01_features/prepare_feat.py` for details.

The directories `data/01_raw_datasets/feat/`, `data/01_raw_datasets/asap2/`, and `data/01_raw_datasets/dysf/` already exist in the repository and are empty; just drop the downloaded files into them.

## 3. Environment Setup

This repository was verified with Python 3.10. Install the dependencies with:

```bash
pip install -r code/00_core/requirements.txt
```

For an exact reproduction of dependency versions, refer to the archived lock file kept by the authors (not distributed with this repository). The NLTK tokenizer and POS-tagging data are provided in `nltk_data/`; if they are missing, run:

```bash
python -c "import nltk; [nltk.download(x) for x in ['punkt','punkt_tab','averaged_perceptron_tagger','averaged_perceptron_tagger_eng']]"
```

Embedding extraction requires a GPU; model training can run on either a GPU or CPU (GPU is faster); the remaining analysis and plotting steps require only a CPU.

## 4. Running and Reproduction

### 0. Prepare the official data

Download the three files described in Section 2 from Kaggle and place them at:

```text
data/01_raw_datasets/feat/training_set_rel3.tsv
data/01_raw_datasets/asap2/train.csv
data/01_raw_datasets/dysf/train.csv
```

These directories are already present and empty; place the files there directly.

Alternatively, use `get_data.py` for automatic download (requires a Kaggle API token):

```bash
cd code/00_core
python get_data.py
```

### 1. Data preprocessing

```bash
cd code/01_features
python prepare_feat.py
python fix_feat.py
python fix_feat2.py
```

`fix_feat.py` computes the 19 linguistic features and takes about 1 to 1.5 hours; `fix_feat2.py` normalizes the score of each prompt to the 0-10 range.

### 2. Embedding extraction

The repository does not include embedding caches, so this step is required (GPU needed):

```bash
export HF_ENDPOINT=https://hf-mirror.com
cd code/00_core
python extract_embeddings.py
```

### 3. M0 sanity check

```bash
python m0_sanity.py
```

It prints `M0 SANITY PASSED` when successful.

### 4. Main experiments

```bash
cd code/02_exp1_non_inferiority
python run_block1.py
```

This script runs P-in, P-LOPO, and P-cross, for a total of 90 training units.

### 5. Ablation experiments

```bash
cd code/03_exp2_ablation_pin
python run_ablation_pin.py

cd ../05_exp4_ablation_lopo
python run_ablation_lopo.py
```

### 6. Auxiliary-task effect and bootstrap

```bash
cd code/08_exp7_auxiliary_task
python run_pin_per_prompt.py
python bootstrap_validation.py
```

### 7. Testing the two hypotheses

```bash
cd code/06_exp5_feature_corr
python analyze_feature_score_corr.py

cd ../07_exp6_gradient_conflict
python analyze_gradient_conflict.py
```

### 8. ARS and leave-one-out robustness

```bash
cd code/09_exp8_ars
python recompute_ars.py
python ars_loo_robustness.py
```

### 9. Selective anchoring

```bash
cd code/10_exp9_selective_anchoring
python run_lopo_5groups.py
```

### 10. Representation alignment (MMD)

```bash
cd code/11_exp10_mmd
python analyze_representation_alignment.py
```

### 11. Non-inferiority CI

```bash
cd code/12_analysis
python CI_Bootstrap.py
```

### 12. Generating paper figures

```bash
cd figures/figure_scripts
python generate_fig1_accuracy.py
python generate_fig2_lopo.py
python generate_fig3_bb_delta.py
python generate_fig4_ars.py
python generate_fig5_validation.py
```

The output overwrites the corresponding PNG files in `figures/paper_figures/`.

## 5. Notes

This repository provides only code, documentation, figure scripts, and NLTK data. It does not include datasets, embedding caches, model weights, or any precomputed results; all numbers reported in the paper are regenerated from the official data by following the procedure in Section 4.

The scripts determine whether a run unit is complete by checking for the existence of `result.json`. No cleanup is needed for a first run; for a full re-run, delete the experiment directories under `results/runs/` first.

The `data/01_raw_datasets/` and `results/runs/_emb/` directories are pre-created placeholders. The pipeline writes its outputs (embeddings, `result.json`, logs, and model weights) under `results/runs/` as it runs.

The paper tables and integration Excel files are result artifacts and are not distributed with the repository. If needed, they can be reorganized from the generated `results/runs/`, or readers can refer directly to the corresponding values in the paper.
